Agents de code + interfaces

ACP connecte l’éditeur à l’agent. AHP synchronise la session entre clients.

Ces deux protocoles ne résolvent pas la même frontière. L’un décrit le dialogue 1:1 avec un agent de code. L’autre décrit comment un hôte partage un état de session cohérent avec plusieurs interfaces.

Chapitre 01 · Situer

1 · Carte mentale

Commence par demander : quelle frontière veux-tu rendre stable ?

Dans un produit agentique, plusieurs frontières se ressemblent : l’éditeur parle à l’agent, plusieurs clients observent la même session, et parfois des agents indépendants se parlent entre eux.

La confusion vient souvent du mot « protocole ». Ici, chaque protocole rend une couture différente prévisible, testable et interchangeable.

Fil conducteur Ne pars pas de l’acronyme. Pars du nombre de clients, de l’autorité de session et du type d’état à partager.

2 · Agent Client Protocol

ACP donne un langage commun à l’éditeur et à l’agent.

Agent Client Protocol standardise la communication entre les éditeurs de code, les IDEs ou autres clients, et les agents de code. Localement, l’agent peut tourner comme sous-processus et parler en JSON-RPC sur stdio ; les scénarios distants passent par HTTP ou WebSocket.

Le point important : ACP ne synchronise pas plusieurs clients. Il décrit surtout la conversation directe qui permet à un utilisateur, via son éditeur, de piloter un agent.

Le dépôt officiel distingue la version des artefacts et la compatibilité réseau : le protocole stable est négocié via protocolVersion pendant initialize, puis les capacités annoncées disent quelles méthodes optionnelles sont disponibles.

Cycle ACP typique initialize
Client → Agent

Le client appelle initialize pour négocier la version du protocole et les capacités disponibles.

3 · Agent Host Protocol

AHP ajoute une autorité de session entre plusieurs clients.

Agent Host Protocol définit comment un serveur de sessions autonome communique avec ses clients. Plusieurs interfaces peuvent se connecter et voir la même session agentique sans inventer leur propre logique de synchronisation.

AHP est encore en développement actif. Son modèle repose sur des canaux identifiés par URI, un état immuable par canal, des actions qui passent par des reducers purs, et une réconciliation quand le serveur renvoie l’ordre autoritaire.

Les clients vérifient aussi les capacités exposées par l’hôte avant d’utiliser une fonction : le protocole cherche la compatibilité progressive plutôt qu’un couplage rigide entre client et serveur.

4 · Ensemble

AHP peut envelopper ACP quand plusieurs clients partagent un agent.

Le modèle Microsoft décrit AHP comme une couche de coordination et ACP comme une couche de communication. L’hôte parle AHP vers les clients, puis traduit les tours vers ACP pour parler à l’agent.

Cette séparation évite de faire porter à ACP des problèmes multi-clients : arbitrage d’un tour en cours, résolution d’une permission depuis une autre interface, annulation, replay et réconciliation.

5 · Piège d’acronyme

ACP peut désigner deux choses différentes.

Dans la documentation Agent Client Protocol, ACP signifie « Agent Client Protocol » : éditeur ou client vers agent de code. Dans l’article IBM, ACP signifie « Agent Communication Protocol » : communication entre agents indépendants.

Les deux sujets appartiennent à l’écosystème des agents, mais ils n’ont pas la même topologie. Quand tu lis « ACP », vérifie toujours les deux mots après le A.

Dans l’article IBM, l’Agent Communication Protocol est pensé pour des agents indépendants, avec une approche REST/HTTP, de la découverte et des échanges synchrones ou asynchrones. Ce n’est pas le protocole qui relie un éditeur à un agent de code.

Nom Frontière Question utile
Agent Client Protocol Client ↔ agent de code Comment un éditeur pilote-t-il un agent ?
Agent Host Protocol Hôte ↔ clients Comment plusieurs UIs partagent-elles une session ?
Agent Communication Protocol Agent ↔ agent Comment des agents indépendants collaborent-ils ?
