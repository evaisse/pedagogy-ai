Agent = modèle + harnais

Un LLM ne devient agent de code qu’avec un harnais.

Le modèle prédit du texte. Le harnais lui donne un espace de travail, une boucle d’action, des outils, de la mémoire, des garde-fous et une façon de vérifier le résultat.

1 · Frontière

Tout ce qui n’est pas le modèle fait partie du harnais.

Un harnais d’agent est le logiciel autour du modèle : consignes système, forme du prompt, outils, exécution, stockage, permissions, orchestration et logique de reprise.

Cette frontière est utile parce qu’elle évite de tout attribuer au modèle. Quand un agent semble meilleur qu’un chat, c’est souvent parce que le harnais lui fournit un meilleur contexte et des retours d’exécution.

Test mental Si l’élément lit un fichier, lance une commande, garde un état ou demande une permission, il appartient au harnais.
01

Modèle

Produit les décisions et le texte à partir du contexte fourni.

02

Instructions, descriptions d’outils et résumé du dépôt restent ordonnés.

03

Observer, choisir une action, exécuter, lire le résultat, recommencer.

04

Fichiers, terminal, sandbox, navigateur, tests et journaux.

05

Transcript, mémoire de travail, plan, diff et historique git.

2 · Boucle

Le harnais transforme une réponse unique en travail itératif.

Un agent de code avance par cycles. Il observe le dépôt, inspecte les indices, choisit une action, l’exécute dans l’environnement, puis vérifie si le résultat rapproche l’objectif.

Cette boucle est la différence pratique entre « donner un conseil » et « corriger un fichier puis prouver que le test passe ».

Boucle observe → agit Observer
Observer Inspecter Choisir Agir Vérifier Réduire

Le harnais collecte les signaux utiles : fichiers, statut git, logs, erreurs de test, sortie terminal et consignes du projet.

3 · Contexte

Le harnais décide ce que le modèle voit maintenant, plus tard, ou jamais.

Le modèle ne garde pas seul une mémoire durable du dépôt. Le harnais reconstruit le prompt à chaque tour en séparant les faits stables, les événements récents et les notes qui doivent survivre à la session.

Préfixe stable

Instructions · outils · résumé workspace

Ordonné pour être réutilisable, cacheable et peu bruyant.

État vivant

Demande · diff · logs · test en cours

Change à chaque tour et reste proche de la décision courante.

Stockage durable

Transcript · mémoire · fichiers · git

Permet de reprendre, compacter et partager le travail entre agents.

Stable Règles + outils + carte du dépôt
Résumé compact Ce qui compte encore
Bord actif Nouvelle demande + observations

4 · Outils et garde-fous

Le modèle demande. Le harnais valide, exécute et borne le résultat.

Un bon harnais ne laisse pas le modèle improviser des actions opaques. Il expose des outils nommés, vérifie les arguments, demande une permission quand l’action est sensible et renvoie une observation exploitable.

Le sandbox et les politiques d’accès font partie de cette couche : ils contrôlent où le code s’exécute, ce qui peut être lu ou écrit, et quels résultats retournent dans le contexte.

Action structurée read_file({ path })
↓
Validation outil connu · chemin autorisé · arguments valides
↓
Permission lecture libre, écriture ou shell sous contrôle
↓
Observation bornée sortie utile, logs longs compactés, erreurs conservées

5 · Travail long

Les tâches longues échouent quand l’état, le contexte et la vérification dérivent.

Les articles insistent sur les mêmes primitives : filesystem et git pour suivre le travail, compaction pour éviter le contexte saturé, tests pour créer un signal de vérité, et sous-agents pour paralléliser ce qui est vraiment indépendant.

01

Plan et trace

Le harnais garde une piste vérifiable : objectif, étapes, fichiers touchés, sorties et décisions.

02

Compaction

Les longs logs et anciens tours sont réduits sans masquer les faits nécessaires à la suite.

03

Vérification

Tests, lint, captures, logs et diff donnent au modèle un retour concret au lieu d’une impression.

04

Délégation bornée

Un sous-agent reçoit une mission étroite, assez de contexte, et des limites claires pour ne pas diverger.

6 · Bac à sable

Choisis une demande et observe quelles couches deviennent indispensables.

Plus la demande touche au dépôt réel, plus le harnais doit ajouter d’état, d’outils, de permissions et de vérification. Le modèle reste le moteur ; le harnais définit le terrain de travail.

Harnais minimum

Contexte court + réponse

Une explication locale peut rester proche du chat, à condition que le bon extrait soit déjà dans le prompt.

Prompt clair Contexte fourni Pas d’exécution

Règle de poche

Quand l’agent réussit, le harnais a transformé l’intelligence en processus.

  1. Le modèle choisit et formule ; le harnais fournit contexte, outils et état.
  2. La boucle observe, agit, vérifie et réduit le contexte pour continuer.
  3. Les garde-fous ne brident pas seulement le modèle : ils rendent son travail exploitable.
  4. La qualité perçue d’un agent dépend autant du harnais que du modèle choisi.
