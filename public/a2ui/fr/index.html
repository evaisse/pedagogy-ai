Agent-to-User Interface

A2UI transforme une réponse d’agent en interface native.

Au lieu d’envoyer du HTML ou du JavaScript, l’agent envoie des messages JSON déclaratifs. Le client garde le contrôle : il valide, résout les données, puis rend ses propres composants.

1 · Modèle mental

A2UI sépare ce que l’agent décide de ce que le navigateur exécute.

L’agent ne pousse pas de code arbitraire. Il choisit des composants dans un catalogue connu, les relie par identifiants, puis attache les valeurs dynamiques à un modèle de données.

Cette séparation explique l’intérêt du protocole : la même intention peut voyager via AG-UI, A2A, SSE ou WebSocket, tandis que chaque client garde son rendu natif.

Surface

Où afficher

Une zone nommée pour une carte, une modale, un panneau ou un fil de chat.

Catalogue

Ce qui est permis

Types de composants, propriétés, fonctions, thème et règles de validation.

Composants

La structure

Une liste plate d’objets avec des IDs ; l’arbre se reconstruit par références.

Data model

L’état

Des chemins JSON Pointer alimentent textes, formulaires, sliders et choix.

2 · Stream

Le rendu arrive par messages successifs, pas par page complète.

En v0.9, le serveur crée une surface, pousse des composants, met à jour le modèle de données, puis peut continuer à modifier la même interface. Le renderer doit tolérer les morceaux manquants pendant le flux.

C’est adapté aux agents : l’interface peut apparaître progressivement pendant que le modèle complète ou corrige sa réponse.

Messages v0.9 Créer la surface
createSurface updateComponents updateDataModel action

Le client réserve une surface et fixe le catalogue qui servira à valider les composants. 

{
  "version": "v0.9",
  "createSurface": {
    "surfaceId": "demo",
    "catalogId": "https://a2ui.org/specification/v0_9/basic_catalog.json"
  }
}

3 · Contrat de rendu

La sécurité vient du catalogue, pas de la confiance dans le texte du modèle.

A2UI limite l’agent à un vocabulaire : composants, propriétés et fonctions explicitement supportés par le client. Dans cette page, la démo expose un petit catalogue A2UI et deux composants du dépôt comme types custom : TokenFlow et SourceList.
